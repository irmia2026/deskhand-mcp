# 人类 UI 操作案例

这些规则用于判断动作的含义，不是所有应用都相同的快捷键配方。先辨认当前模式，再采用对应路径。工具的窗口 focus 不是此处的控件焦点证明。

按需要查对应案例，不逐条执行。文中的“完成标志”用于理解结果，可来自已有画面或工具返回，不要求额外调用；verified=true 不再重复回读同一值。稳定流程连贯执行，一段结束再观察，只有异常才增加检查。

## 1. 把输入框的全部内容换成新内容

**前置：**确认是目标输入框，而不是旁边的标签；明确本次是覆盖，不是追加。

**顺序：**能直接设置值时设置并回读；走键盘时，先聚焦该字段，再全选，再输入。全选后不再点字段，双击通常只选一个词，不能代替整字段全选。若是可编辑组合框，要区分文本区和下拉按钮。

**完成标志：**读回恰好等于新值，没有旧值残留或额外换行。光标出现在末尾不是“内容已替换”的证明。

**错了如何恢复：**先读实际内容，确认键盘作用于哪个字段；若仍是用户指定字段，可以重新整字段设置。不要仅因出现重复字符就按不确定范围的撤销。

## 2. 设置颜色、尺寸、缩放等参数，然后继续工作

**前置：**辨明字段格式和单位，例如 hex、RGB、百分比、像素；确认输入的是值，不是可拖动标签或滑块。

**顺序：**更改值 → 检查字段 → 按该应用实际约定采用／提交 → 检查相关色块、尺寸或视图。若自动实时生效，则不额外按可能触发默认按钮的 Enter；仍需保留“编辑可能未结束”的状态。

**完成标志：**字段和业务效果都符合预期。准备跨到画布或执行快捷键时，还需确认编辑状态和作用域。

**陷阱：**Tab 会移动焦点但可能先提交或校验；Esc 可能恢复旧值；Enter 可能关闭整个弹窗。无明确证据不把任何一个当万能提交键。

## 3. 选中对象、编辑对象、移动对象

**前置：**明确目标是对象、对象中的文字，还是像素选区；确认当前工具。

**顺序：**使用选择／移动工具 → 选中目标 → 检查对象名称、边框、控制柄或列表选择状态 → 执行移动／属性修改。进入文字编辑后，同样的箭头键可能移动光标而不是对象。

**完成标志：**指定对象的位置或属性改变，内容没有被误改。

**陷阱：**单击可能只选择；双击可能进入编辑、打开文件或执行默认动作。不要用加快点击或双击代替“不知道第一次做了什么”。

## 4. 拖动、绘画、缩放和滚动

**前置：**确认工具、起点所属对象和命中区域。对象内部、边缘控制柄、窗口边框、滚动条有不同含义。

**顺序：**选择所需工具／模式 → 观察模式已激活 → 在合适的命中区域按下 → 持续移动 → 松开 → 检查目标结果。连续笔画只按下和松开一次。

**完成标志：**移动了目标对象、改变了尺寸或画出目标笔画；不能只看鼠标走到了终点。

**陷阱：**在画笔模式下“点画布聚焦”会画点；在移动模式下拖拽会移动图层。滚轮可能作用于鼠标下区域、焦点数值框或应用缩放；发生意外变化时先识别接收者，不重复滚动纠正猜测。

## 5. 从文字编辑切回工具快捷键

**前置：**最近输入过文字／参数时，默认仍可能存在文本编辑上下文，不推定鼠标操作已解除它。

**顺序：**根据应用完成编辑；使用明确的工具按钮切换，并检查激活状态。只有已知当前不是文字输入、且该应用快捷键含义可靠时，才使用 B、V、空格等按键。

**完成标志：**工具栏状态、工具名称或指针反馈符合预期，参数文字没有混入快捷键字符。按钮被 invoke 不证明输入框失焦。

**恢复：**若字母进入字段，先核实字段和提交状态；仅恢复被误改的指定参数，然后重新采用它。不靠无上下文的全局撤销处理。

## 6. 删除选中内容

**前置：**明确“删字符”“删图层”“删对象”“清除选区像素”是哪一种，并确认实际选中对象。

**顺序：**能用命名明确的对象命令时用它；使用 Delete 前检查接收者与当前模式。输入框光标、图层列表选中行、画布选区可能同时存在，不能任选一个当证据。

**完成标志：**指定对象消失或清空，不相关字段、图层和内容保留。

**恢复：**先识别被删对象再决定恢复路径；不要假设 Ctrl+Z 一定恢复刚刚看到的变化。

## 7. 菜单、下拉列表和弹窗

**前置：**区分展开按钮、当前选项、输入区及被遮挡的主窗口。

**顺序：**打开菜单／下拉 → 观察新出现的候选 → 选择具体条目 → 检查最终选中项和展开状态。对话框出现后先处理它的字段与按钮，再回主窗口。

**完成标志：**选中的实际值正确，或弹窗已按要求结束。点击位置正确但主窗口没变化，可能是被模态框阻挡。

**陷阱：**首次点击可能只展开菜单；菜单覆盖原界面，旧坐标变成菜单项。Enter 可能执行默认按钮，Esc 可能关闭弹层或取消整个编辑；需判断当前层级。

## 8. 保存／导出

**前置：**确认是保存当前文档、另存新副本还是导出；三者可能改变活动文档、格式和图层保留方式。

**顺序：**打开正确命令 → 处理文件名、目录、格式和可能的选项弹窗 → 确认最终提交 → 观察是否仍有后续对话框或后台处理。

**完成标志：**目标路径和格式正确，应用完成操作；能检查产物时检查落盘内容。文件名字段填好、点击了保存或某个弹窗关闭，均不是整个保存流程必然完成的证明。

**陷阱：**Enter 可能确认自动补全而未保存；扩展名与格式下拉可能不一致；保存成功也可能不改变当前文档名。依任务需要验证，不只认标题。

## 9. 撤销与重做

**前置：**明确要恢复哪个对象的哪一次修改；文本框和文档可以有不同历史，应用也可能合并多次操作。

**顺序：**查找对象明确的历史项／撤销命令 → 确认范围与目标修改相符 → 执行一次 → 检查目标变化与应保留状态。上下文不明时不采用 Ctrl+Z；普通撤销菜单也需要辨明作用范围。

**完成标志：**目标笔画或修改恢复，颜色字段等无关状态保留。操作序列的“上一步”不能代替应用的真实历史条目。

**恢复：**误撤销后先检查真正改变了谁。Ctrl+Y 也可能发给错误对象；重新设置参数又可能新增历史，不能通过多发几个 Undo／Redo 找回预想状态。

## 10. 遇到尚未识别的交互

先判断控件属于输入、选择、触发命令还是持续手势；查当前可见状态、提示和明确命令。完成一次可判断的动作后看新状态，不执行凭经验拼出的长串按键。用户熟悉软件并不意味着模型也已知道它的默认按钮、提交方式或快捷键路由。

如果所需状态没有被工具暴露，也无法从当前 UI 可靠辨认，保留未知并选择不依赖该状态的明确操作；没有替代路径时说明具体缺口。不要用破坏性试探建立操作知识。
