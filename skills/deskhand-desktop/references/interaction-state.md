# 交互状态与作用域

## 六个状态，不相互替代

| 状态 | 能证明什么 | 不能推出什么 |
| --- | --- | --- |
| 前台窗口 | 系统把哪个顶层窗口作为前台 | 某个输入框不再接收键盘 |
| 鼠标命中／捕获 | 哪个控件接收本次点击或拖动 | 后续快捷键也会交给它 |
| 键盘焦点 | 哪个控件可能接收普通键盘输入 | 全部快捷键均由它处理；应用可能有独立路由 |
| 编辑事务 | 输入是否仍处于未提交／可取消的编辑状态 | 字段显示正确就一定提交了 |
| 活动上下文 | 当前工具、图层、选区、文档和模态窗口 | 最新操作一定属于预想的对象 |
| 撤销历史 | 文本框或文档各自记录了哪些修改 | 最近调用的 MCP 动作必然位于同一撤销栈 |

工具成功返回，仅证明对应结果字段陈述的事实。已派发、值回读一致、画面变化、参数生效和编辑结束，要分别判断。

**当前工具边界：**这版 Deskhand 的 focus 策略和 focus_changed 主要围绕顶层窗口；press_key 没有针对文档／字段的作用域参数。没有通用的键盘焦点和撤销栈查询工具，不要虚构 get_focus、undo_document 或未注册参数。不能观测的状态标为未知，不当作安全已确认。

## 出现作用域疑问时的处理思路

仅在下个动作的接收者不明确或已有异常征兆时使用。正常提交参数后继续工作，不要求每次切换对象都跑一遍。下列条目说明如何判断，不是五次工具调用；能复用现有返回或画面就复用，尤其不要重复回读已验证的值。

1. **声明意图：**下个动作要修改哪个对象？例如“撤销活动文档的最后一笔，不修改颜色输入框”。
2. **完成当前事务：**寻找该应用明确的应用／确定／完成编辑控件；需要时使用已知适用的提交方式。Enter、Tab、Esc 没有通用含义，不能统一规定按某一个键。
3. **验证参数与上下文：**颜色字段／色块／画笔状态是否符合预期？模态框是否关闭？图层和选区是否正确？read_value 能确认字段值，但单独不能证明提交或失焦。
4. **选择不依赖未知焦点的动作：**优先应用明确作用于文档的命令、历史项或带清楚对象名称的界面操作。普通“编辑→撤销”也可能路由到输入框，必须看具体标签、描述或历史范围，不能把走菜单视为天然安全。
5. **核验正确对象的变化：**撤销笔画后应见该笔消失；不该改变的颜色参数应仍一致。全局像素变化不能代替这两项检查。

点击画布、隐藏光标、去掉选中高亮，都不是普遍可靠的失焦证明。盲点一下画布还可能留下额外笔点。不要为“获取焦点”制造新的文档修改。

## 用户例子：绿色 hex → 绘画 → 撤销

已知输入过颜色、随后画出错误笔画，但不知道键盘接收者。此时状态是“画布收到过鼠标，键盘／撤销作用域未知”，不是“画布已经接管一切”。

正确路线：确认颜色编辑提交与当前文档 → 寻找文档历史面板、明确的“撤销画笔／笔刷”等命令 → 只撤销目标笔画 → 检查画布和颜色都符合预期。没有足够证据时，不发送猜测性的 Ctrl+Z，也不先制造试验笔画来推断焦点。可继续不依赖该撤销的独立步骤，或说明缺少可靠的文档撤销入口。

如果误撤销已经发生：先检查颜色字段、色块与画布，确定究竟哪个对象变了。不要凭预想发送 Ctrl+Y，因为重做也有作用域。确认后恢复被误改的参数，再选可靠的文档撤销路径；恢复参数本身还可能新增历史记录，不能靠计数补发撤销。

## 同类容易误用的操作

| 期望 | 隐藏的其他含义 | 行动原则 |
| --- | --- | --- |
| Ctrl+A 选画布全部 | 全选颜色或尺寸文字 | 作用域不明时走明确的文档选区命令 |
| Delete 删除图层 | 删除文本、对象或选区内容 | 指定当前目标并验证选中对象，不凭最近点击判断 |
| B／V／空格切工具或平移 | 在输入框输入字符／空格 | 未确认退出文本编辑时优先工具按钮 |
| Enter 提交参数 | 插入换行、确认模态框、触发默认按钮 | 根据当前控件／对话框选择明确提交方式 |
| Esc 退出输入框 | 取消刚填的值、关闭对话框、取消选区 | 不把 Esc 当通用失焦键 |
| 滚轮滚动文档 | 修改数值框、缩放画布、滚动侧栏 | 明确滚轮目标与修饰键，验证实际变化 |
| 拖动移动对象 | 当前工具是画笔，画出一笔 | 先确认工具、选区／对象、图层与起点 |
| 写入数值已回读 | 应用只在提交时重新计算／采用 | 同时检查业务效果，不仅检查字符串 |

## 错误恢复也必须有作用域

在任何撤销前写出“撤销哪个对象的哪一次修改”。如果无法回答，不批量 Ctrl+Z。Undo 不是全局回滚，Redo 也不是无条件恢复。不同控件可以有各自历史，应用还可能将数笔合并为一个记录。

优先根据可识别的历史条目恢复；确需快捷键时，须已有该应用当前上下文的可靠证据，且一次后就验证。普通焦点视觉线索只能补充判断，不能消除未知的快捷键路由。
