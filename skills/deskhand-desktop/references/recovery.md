# 恢复策略

失败先分类，下一次操作须基于新增证据，不原样重放长串动作。

| 现象 | 下一步 |
| --- | --- |
| paused=true／用户物理 Esc | 停止任务输入；可 status 或 exit。无明确许可不 resume |
| stale／无绑定／窗口关闭 | list_windows 确认，再 look(hwnd=...)；丢弃旧编号、游标和图映射 |
| 多个同名候选 | 加类型、位置、上下文；看局部图；不按数组顺序猜 |
| 目标没出现在第一页 | find_element 查全部已收集项；需要浏览才用 next_cursor；新 look 后旧 cursor 失效 |
| 采集 truncated=true | 分页不能补采集；改 OCR/CV，滚动暴露目标、展开控件或选正确子窗口再观察 |
| 后台／落点不属于目标 | 检查弹窗、遮挡和任务窗口；允许置前时用 auto 再观察，不改 screen 绕过保护 |
| 点击或输入 uncertain | 读字段、选区、控件状态或目标产物，防止重复输入／双重提交 |
| 调用超时 | 不假定底层动作被取消；先核实界面，尤其保存、提交和追加 |
| ready=false | 可能已启动为单实例／UWP／子进程；列窗口确认，不立即重启 |
| wait_change 超时 | 只比较调用开始后的画面；动作可能此前已完成，重新查看预期状态 |
| 撤销／删除影响了错误对象 | 先核实字段、文档、工具和历史范围；读 [交互状态与作用域](interaction-state.md)，不盲目补发 Undo／Redo |

画面被遮挡且任务不允许抢焦点时，优先后台 UIA 读取；不把屏幕上的遮挡内容认作目标窗口内部状态。

等待应围绕“导出完成”“对话框出现”“字段读回一致”等状态。必要时短 `wait_change(timeout=2)` 辅助等待，changed 后仍检查目标；不用固定长休眠代替观察。

同一子目标用两种不同证据来源仍无进展时，停止盲试并记录缺少的信息；可推进的独立工作继续。需要用户判断时只问关键差异，如两个同名文档选哪一个，不要求用户提供工具本可取得的坐标。

结束本轮电脑操作时 exit，即使任务未全部完成。退出只清理覆盖层，不保存或关闭用户文档。
